# Data formats

English | [中文](data-format.md)

The board reads files from the `data/` directory. Only `universe.json` is required. The other two sets are optional; without them the page skips the matching features (the local server answers 204 for a missing optional file, so the page does not report an error).

## `data/universe.json` (required)

The stock list, generated by `python tools/update_universe.py`.

```json
{
  "asOf": "2026-11-10",
  "industries": ["白酒Ⅱ", "银行Ⅱ", "..."],
  "stocks": [
    ["sh600519", "贵州茅台", 0, 3580000000],
    ["hk00700", "腾讯控股", 12, 15600000000],
    ["usAAPL", "苹果", 40, 54700000000]
  ]
}
```

- Each row of `stocks` is `[code, name, industry index, turnover]`.
  - Code format: `sh` / `sz` / `bj` + 6 digits, `hk` + 5 digits, `us` + the US ticker.
  - The industry index points into `industries`. Stocks of the same industry cluster together on the nebula.
  - Turnover is in each market's own currency. It only sets the dot size, and the page replaces it with live turnover.
- The row order is the order of stocks in the nebula. The rows of `history.bin` must be in the same order.
- Names come from the data source and are in Chinese. In the English interface, industry names that the page knows are shown in English; stock names are shown as they are in the file.

## `data/history.json` + `data/history.bin` (optional: after-close replay, factor IC)

Once every market has closed, the page replays the real daily moves of the whole market over recent days, and uses the same data to compute the Rank IC shown in the Factors panel.

`history.json`:

```json
{
  "days": ["2026-08-03", "2026-08-04", "..."],
  "rows": 8564,
  "cols": 60,
  "indices": {
    "sh000300": { "close": [3900.1, 3912.4], "prev": [3890.0, 3900.1] },
    "hkHSI":    { "close": [], "prev": [] },
    "usINX":    { "close": [], "prev": [] }
  },
  "dayAmount": [1.21e12, 1.33e12]
}
```

- `days`: trading days, oldest first. Its length equals `cols`.
- `rows`: must equal the number of stocks in `universe.json`. If it does not, the page does not replay.
- `indices`: the benchmark indices' close and previous close for each day (aligned with `days`), used by the indices at the top and the volatility funnel during replay. You may provide only some of them.
- `dayAmount`: total A-share turnover per day, in yuan. Optional.

`history.bin`: `rows × cols` signed 16-bit integers (little-endian), stored row by row. Day `k` of stock `i` is at index `i * cols + k`.

- Each value is the day's percentage change times 100 (`+2.35%` is stored as `235`). Missing or suspended is `-32768`.
- The representable range is ±327%. Clip anything beyond that to ±320% (the page treats ±320% as a cap and keeps such values off the movers ring).

## `data/rules.json` (optional: rule signals, backtests)

The results computed from your own screening rules. The page only displays them: the stocks that meet each rule today, the backtest net value, and the follow-up tracking.

```json
{
  "asOf": "2026-11-07",
  "rules": [
    {
      "id": "MY_RULE",
      "title": "Rule name",
      "tagline": "One-line description",
      "summary": "Full description of the rule",
      "poolSize": 3200,
      "hits": [
        {
          "code": "sh600519", "name": "贵州茅台", "stars": 4,
          "headline": [["P/E", "22.0"], ["Last 20 days", "+3.1%"]],
          "checks": [["P/E below 30", true, "22.0"], ["Above the 60-day average", false, "1.2% short"]]
        }
      ],
      "backtests": {
        "A": {
          "start": "2024-01-02", "end": "2026-11-07", "periods": 34,
          "ruleReturn": 0.31, "benchmarkReturn": 0.12,
          "maxDrawdown": 0.18, "benchmarkMaxDrawdown": 0.22, "beat": 20,
          "daily": [["2024-01-02", 1.0]],
          "benchmarkDaily": [["2024-01-02", 1.0]],
          "events": [["2024-01-03", "buy", "sh600519", "贵州茅台", 100, 1650.0]],
          "buys": 170, "blockedBuys": 3, "delayedSells": 2, "costRatio": 0.012,
          "note": "Rebalanced every 21 trading days, 5 equal-weight holdings; filled at the next open, commission and stamp duty included"
        }
      }
    }
  ],
  "tracking": [
    { "rule": "MY_RULE", "market": "A", "horizon": 5, "days": 12, "avgReturn": 0.004, "avgExcess": 0.002, "beatShare": 0.58 }
  ],
  "trackingSince": "2026-10-20"
}
```

- Required fields:
  - Every rule needs `id`, `title`, `tagline`, `summary`, `poolSize` and `hits`. When no stock meets the rule, set `hits` to an empty array `[]`. If the field is missing, the whole file is treated as having no rule data.
  - Every matching stock needs `code`, `name`, `stars`, `headline` and `checks`.
  - Every backtest needs all the fields in the example above except `note`.
- `stars` is an integer from 0 to 5. It says how well the data matches the rule's conditions; it is not a forecast of price moves.
- `relaxNote` (optional, on a rule): a one-line notice shown under the rule name, for example to say that a condition has been temporarily relaxed.
- Keys of `backtests`: `A` (A-shares, compared with the CSI 300), `HK` (Hong Kong, compared with the Hang Seng) and `US` (US, compared with the S&P 500). Leave out the ones you do not have; you can then give a `noBacktestReason` to explain why.
- Returns and drawdowns are decimals (`0.31` means 31%). Net value series start at 1.
- `note` (optional, on a backtest): how this backtest was run (rebalancing period, number of holdings, cost assumptions and so on). The page shows it as written under the backtest card; without it nothing is shown.
- `events` are the simulated fills in the backtest: `[date, "buy" | "sell", code, name, shares, price]`. They are shown when the replay reaches that day.
- The text in this file (titles, descriptions, headline labels, notes) is shown exactly as you write it, in either interface language.
